# 标准生产流程

## 自动模式

本地日常制作优先运行 `npm run book:auto`。运行前必须把合法取得的完整原文以 UTF-8 `.txt` 或 `.md` 放入根目录 `source/`，并用 `--source` 指定文件名。该命令仍然复用下文全部 npm 门禁和生产脚本，只由一次可恢复的 Codex CLI 会话读取绑定原文、填写内容、调用图片生成并推进各阶段。命令启动本身视为当前书从本地原文读取到最终交付的明确授权，因此通过脚本自审和质量门后无需再次等待人工批准；自动授权不包含联网研究、抖音或其他外部平台发布。

自动模式默认隐藏 Codex 命令、代理说明和子进程噪声，只在同一条终端进度栏显示八个关键阶段、素材计数、渲染进度、已用时间与最近活动。完整 JSONL、stderr 和最终交付复检日志仍写入 `.runtime/book-auto`。网络事件单独提升为可见状态：显示当前重连次数、等待网络或 WebSocket 转 HTTPS，并提醒用户在持续异常时切换网络节点；下一条正常事件到达后标记网络已恢复。只有真正阻塞或最终验收失败时才打印关键原因、日志路径和恢复命令。需要原始过程时使用 `npm run book:auto -- --resume --book <book-id> --verbose`。

自动流程不得递归调用 `book:auto`，不得联网搜索书评、剧情梗概或访谈，只能读取已绑定的 `source/` 原文并调用 `book:quality`、`book:review`、`book:approve`、`book:produce` 等现有底层命令。遇到原文缺失、SHA-256 变化、正文不完整、认证或额度失败，以及同一质量问题连续三次修复仍未通过时，保留有效产物并停止；修复后使用 `npm run book:auto -- --resume --book <book-id>` 继续原 Codex 会话。

以下分阶段流程仍用于人工干预和排错。

## 阶段 A：新建与脚本审批

1. 用户把完整原文放入根目录 `source/`，再运行 `npm run book:new -- --title <书名> --author <作者> --source <文件名>` 创建并选中新书。
2. 建书脚本验证原文位于 `source/`、编码为 UTF-8，并把项目相对路径与 SHA-256 写入 `content/source-map.json`；Codex 不进行联网搜索。
3. Codex 生成 `content/script.json`、`content/source-map.json` 与 `content/publish.json`；发布物料包含一句简洁吸睛的标题和 1～2 句有趣简介，并与脚本承诺一致。成品固定追加 `#保持阅读 #书籍分享 #个人成长 #认知提升`，无需每本书重复填写。
4. Codex 先完成专名与读音、开场留存、持续留存结构、逐句通顺、来源一致性、故事覆盖、原创评论、通用内容链、内容层边界、关键画面和固定收尾等自审，并把当前脚本 SHA-256 写入 `source-map.json.selfReview`。
5. `npm run book:quality` 通过后，`npm run book:review` 生成内部审稿归档；`book:review` 会自动复跑质量门。
6. Codex 只向用户交接“审核通过，继续下一步就行”，用户默认无需逐字审稿。
7. 用户提出修改时回到第 3～5 步；否则用户以“脚本已批准，开始生成分镜、原创插画和两种发布封面”明确授权进入视觉阶段。
8. Codex 收到授权后运行 `npm run book:approve` 和 `npm run book:approval-check`，用 SHA-256 锁定脚本，再进入阶段 B。

这一阶段不生成分镜、插画、配音和视频，不产生 TTS 与图片生成成本。

### 脚本自审硬规则

- 第一段第一句话必须直接落钩，钩子在前 2 秒出现；不得先报书名、作者、栏目或“今天我们来讲”。
- 前 10～20 秒必须兑现第一个事实、结论或证据，并立即引出下一问题；不得把一个悬而不答的问题拖成整段。
- 引言总目标为 30～45 秒，`retentionPlan.introductionSegmentIds` 从第一段起连续标记引言范围；第一处具体场景必须最迟在 45 秒开始。
- 后续约每 20～40 秒完成一次“小兑现＋新悬念”。`script.json.retentionPlan.segmentBeats` 必须与口播段落一一对应，记录每段的 `sourceAnchor`、`payoff` 和下一段的 `nextHook`；最后一段可以不再设置 `nextHook`。
- 所有题材默认服务没读过原著的观众。小说要讲清人物、目标、阻碍、关键场景、反转、后果和结局，不得用“不复述具体剧情、反转或结局”回避原著核心内容；非虚构作品要讲清原著案例、论证步骤、结论成立条件和局限。至少 60% 段落的 `sourceAnchor` 必须记录新增的具体原文场景或案例，纯分析段留空，且不得连续超过两个纯分析段。
- `script.contentFlow.loops` 至少完成一条“现实问题→具体场景→原著核心案例或剧情→解释原理→回到现实→补充局限”；相邻阶段可以共享段落，避免六段式生硬拼接。
- `segmentBeat.contentLayers` 必须区分原著内容、现代类比、本频道判断和过渡；成片用自然口播提示边界，不显示机械分类标签。
- 每个情节段落必须回指绑定原文的具体行号。书评、剧情梗概、作者访谈和模型记忆不能作为补充来源。
- 前两段不得设置“阅读边界”“先分清史实和小说”等独立免责声明段；事实边界只在具体内容需要时自然嵌入。
- `source-map.json.terminology` 至少登记一组需要核对的专名，并列出标准写法；遇到多音字时同时记录读音，遇到易错字时列出 `avoid`。
- Codex 必须逐句按口播朗读，主动发现病句、生造口语、歧义、重复和凑字数内容。
- 工程校验通过只表示结构、引用和规则可执行，不代表文案已经通过编辑审查。
- Codex 必须自行完成编辑审查；质量门失败或语义自审存疑时继续修改，不得要求用户逐字排错。
- `selfReview.scriptSha256` 必须等于当前 `script.json` 的 SHA-256；脚本变动后旧自审立即失效。
- `selfReview.checks.storyCoverageReviewed` 必须为 `true`；这表示已逐段确认分析建立在具体原文故事上，而非抽象观点堆叠。
- `contentFlowReviewed`、`contentLayerDistinctionReviewed`、`semanticVisualMomentsReviewed` 和 `closingBrandLineReviewed` 必须为 `true`。
- 最后一段最后一句固定为“这里是陈拾叁，陪你一起读书破万卷。”，且整条视频只出现一次。

## 阶段 B：视觉制作

1. Codex 根据批准脚本设计 `content/visual-plan.json`。
2. 先挑选关键剧情、原著核心案例、关键概念、现代类比和局限反思，再决定画面；不得按固定时间间隔或固定数量凑图。
3. `visual-plan.json.keyMoments` 将每个关键内容映射到具体镜头；每个脚本段按需要使用 1～4 个镜头，`weight` 决定相对停留时间。
4. 生成原创分镜插画和封面插画；图片模型不得生成英文、字母、数字、标志、水印、中文或乱码文字，必要中文由 Remotion 排版。
5. 配置了 `portrait-2x2-9x16-v1` 的新书，每张分镜必须保存为纵向 9:16 PNG 母图，内部固定 2×2，四个子画面也各自为 9:16，顺序为左上、右上、左下、右下。禁止使用正方形四宫格；允许 0.5% 像素取整误差。
6. 图片保存后逐张确认关键内容覆盖且无英文/乱码，将 `assetReview.semanticCoverageReviewed` 与 `assetReview.noEnglishVisible` 标为 `true`，再运行 `npm run book:storyboards-check`。检查通过前不得开始 TTS 或渲染。
7. 默认使用明亮日光或充足天光，暗部保留细节；严肃题材也不得自动转为低调黑暗画面。
8. 新书视频空白首帧固定为纯黑色；插画仍保持明亮通透。顶部常驻文字只保留居中的准确书名，不带“10分钟读书”标签。字号为 42～48px且小于章节重点字；章节重点字至少展示 6 秒，并按每字约 0.35 秒延长阅读时间。
9. 新书开头运行 2.8～4.8 秒的 `book-picker-v1` 选书动画，并与第一句口播钩子同时开始。动画使用原创无字封面底图和代码排版书名，不接收原书版本封面截图。
10. 从 `book-003` 开始只制作抖音发布中心实际使用的 3:4 和 4:3 封面，不再生成 9:16。封面必须采用原创书籍正面版式，真实书名是最大文字；作者和一句推荐语降为次级信息。图片模型只生成无文字封面插画，准确书名由 Remotion 排版。
11. 将 `source-map.json.terminology` 中 TTS 可能误读的多音字写入 `narration-config.json.pronunciationOverrides`；正文保持标准写法，替换文本只发送给 TTS。

## 阶段 C：自动生产

运行 `npm run book:produce`：

```text
批准哈希检查
→ 素材预检
→ 刘飞男声 -10 口播
→ 音频主时钟与镜头排期
→ 工程验收
→ 有声视频
→ 3:4 与 4:3 两种书名型封面
→ 发布标题与作品简介
→ 交付文件验收
```

## 阶段 D：发布后处理

1. 将 `output/final.mp4` 导入剪映。
2. 剪映一键识别字幕并人工检查。
3. 导出最终发布视频。
4. 抖音网页版上传 3:4 和 4:3 发布封面。
5. 从 `output/publish-copy.txt` 复制标题和作品简介。
6. 默认不添加章节信息。

## 返工规则

- 修改脚本：重新 `book:review`、`book:approve`，口播会因哈希变化自动重做。
- 修改多音字发音覆盖：不改批准脚本；发音规则哈希变化会自动使旧口播缓存失效，再运行 `npm run book:produce`。
- 只改分镜或插画：保持批准脚本不变，复用原口播。
- 只改封面：运行 `npm run book:covers`。
- 只改视频模板：运行 `npm run book:render`。
- 字幕只在剪映维护，Codex 工程不生成 SRT。
- 新书不得使用“这里是十分钟读懂一本书”；最后一句固定为“这里是陈拾叁，陪你一起读书破万卷。”。
- 本次标准升级不修改 `book-001`、`book-002`、`book-003` 的已有配置、素材或交付文件。
